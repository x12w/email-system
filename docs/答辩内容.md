# 邮箱系统 · 前端PPT文本

---

## 第1页：技术栈 & 架构

| 技术 | 说明 |
|------|------|
| **Vue 3 + TypeScript** | Composition API，全量类型覆盖，杜绝隐式 any 类型 |
| **Vite** | 模块热替换、开发代理转发、生产构建 |
| **pnpm** | 确定性依赖管理 |
| **Vue Router 4** | 6 条路由，路由守卫三层鉴权（未登录重定向 / 已登录自动跳转 / 用户信息预加载） |
| **Pinia** | 5 个 Store 模块（auth / mail / folder / contact / intelligence） |
| **Element Plus** | 按需自动导入（表格/弹窗/表单/标签/分页） |
| **Axios** | 统一请求封装、Token 注入、响应解包、401 静默续期 |
| **质量** | TypeScript 编译零错误、生产构建通过、16 组 DTO 字段严格对齐 |

## 前端答辩稿

我们前端基于 Vue 3 的 Composition API 开发，全部组件用 `<script setup>` 写法。
整个应用是单页面架构，通过 Vue Router 管理六个核心路由：
登录、收件箱、邮件详情、写邮件、通讯录、设置。

路由守卫在每次跳转前检查 token 是否存在：
需要鉴权的页面如果没有 token 会被重定向到登录页，
已登录用户访问登录页会自动跳回收件箱，
首次加载时还会自动请求当前用户信息。

---

状态管理用了 Pinia，拆了五个 Store 模块和业务一一对应：
认证 Store 管理登录态和 token 持久化，
邮件 Store 管理列表数据和分页筛选条件，
还有文件夹、联系人、AI 分析的 Store。

组件里通过 Store 拿数据，不用自己维护本地状态，
多个页面共享同一份数据也保持一致。

---

和后端通信用的是 Axios，封装了一个统一的请求实例，
配置了请求拦截器和响应拦截器。

请求拦截器自动在每个请求头注入 Bearer token，
响应拦截器统一解包后端返回的 JSON 结构，
遇到 401 会自动尝试刷新 token，
刷新成功重发之前挂起的请求，
刷新失败才跳转登录页，用户全程无感知。

---

UI 层用 Element Plus 组件库，按需自动导入，不用的组件不会打进包里。
邮件列表用 el-table 展示，分页用 el-pagination，
筛选栏用 el-select 支持多条件组合，
包括智能分析的三个维度——垃圾邮件标签、优先级、风险等级。

邮件详情页集成了 AI 分析面板，
用进度条展示置信度分数，威胁项用表格列出。

写邮件页面的收件人输入框支持从通讯录自动补全联系人，
富文本编辑器支持 HTML、纯文本、富文本三种模式切换。

---

TypeScript 方面，我们给所有 API 的请求参数和响应数据都定义了完整类型。
前后端约定了 31 个端点，
每组 DTO 和前端类型的字段名、类型完全一致，
避免了联调时字段对不上的问题。

整个项目杜绝隐式 any 类型，
只有 Axios 封装层有一处类型桥接是必须的。

---

构建用的是 Vite，开发时代理转发 API 请求解决跨域，
生产环境打包成静态资源交给后端或 Nginx 托管。

包管理器用的 pnpm，依赖管理更高效。
