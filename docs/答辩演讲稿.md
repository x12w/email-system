# 电子邮件系统 — 答辩演讲稿

---

## 第 1 页 · 封面（10 秒）

各位老师好，我做的毕业设计题目是「电子邮件系统」——一个基于 Spring Boot 和 Vue 3 的全栈智能邮件管理平台。

项目实现了 SMTP/IMAP 真实的邮件收发、AI 智能分析、以及完整的安全防御体系，目前已部署在线上。

---

## 第 2 页 · 项目概述（90 秒）

先说一下为什么要做这个项目。市面上的邮件客户端比如 Outlook、Thunderbird 功能很全，但它们是桌面软件，不能自己部署、不能定制。我想做的是一套**可以自己掌控的邮件系统**——自己部署、自己管理数据、自己扩展功能。

项目定位有四点：第一，全栈自研，后端 Java、前端 Vue，没有用现成的邮件客户端框架；第二，基于标准协议实现真实收发，不是 Mock；第三，集成 AI 分析管线；第四，注重安全性和可部署性。

核心成果：后端约 30 个 Java 类，前端约 10 个组件，数据库 14 张表，完整的功能闭环。支持 Gmail、QQ、Outlook、163 等主流邮箱，Docker 一键部署，线上已经在运行。

技术选型方面，前端是 Vue 3 + TypeScript + Element Plus，后端是 Spring Boot 3 + Spring Security + MyBatis-Plus，数据层 MySQL 加 Redis，AI 引擎用 Python 原生插件通过 JNI 调用。

部署上，Docker Compose 管理 7 个服务——MySQL、Redis、MinIO、Mailpit、Nginx、后端、mailserver，Nginx 做反向代理，Let's Encrypt 自动签发 SSL 证书。

---

## 第 3 页 · 系统架构（60 秒）

这是系统的六层架构。从下往上看：最底层是 AI 引擎层，用 Python 原生动态库做智能分析，Java 通过 JNI 调用；往上是数据层，MySQL 做主存储、Redis 做缓存、MinIO 存附件；业务层实现邮件收发、IMAP 同步、智能分析编排；应用层是 Spring Boot REST API，统一异常处理和响应格式；网关层 Nginx 做反向代理和 SSL；最上层是 Vue 3 单页应用。

各层职责清晰，层与层之间通过标准接口通信，模块之间松耦合。

---

## 第 4 页 · 核心功能（90 秒）

系统有四大功能模块。

**邮件收发**：支持绑定多个邮箱账号，SMTP 和 IMAP 独立配置，SSL/TLS 自适应——端口 465 走 SSL 直连、端口 587 走 STARTTLS。文件夹自动同步，未读计数实时从数据库计算。支持搜索、筛选、分页、草稿、删除、附件上传下载。

**智能分析**：每封邮件入库后自动进入分析队列，Python 插件做三件事——垃圾检测、优先级评分、风险识别。插件不可用时自动降级到 Java 规则引擎，超时 2 秒熔断，不阻塞主链路。

**安全体系**：这个后面有专门一页讲，简单说就是 JWT 双 Token、BCrypt 密码加密、登录限流、API 异常脱敏、CORS 显式配置、数据按用户隔离。

**用户管理**：注册登录、Token 刷新、多租户邮箱隔离——同一个邮箱地址可以被不同用户分别绑定，互不影响。还有联系人管理和 Dark Mode 主题切换。

---

## 第 5 页 · 智能邮件分析（60 秒）

这页详细讲 AI 分析管线。流程是五步：邮件入库 → 分析任务入队 → Python 插件执行分析 → 结果写回数据库 → 高风险时触发推送通知。

三个分析维度：垃圾检测用关键词匹配、发件人信誉、文本特征；优先级识别关注紧急词汇和时间敏感度；风险检测检查 URL 里的 IP 地址、短链接、敏感关键词。

插件接口非常简洁——`analyze_email_json(json) → json`，输入一封邮件的 JSON，输出分析结果的 JSON。超时 2 秒，不可用时自动 fallback 到 Java 规则引擎，保证邮件主链路不受影响。插件版本可以回溯，支持热替换。

---

## 第 6 页 · 数据库设计（45 秒）

数据库用了 MySQL 8.0，14 张表，分五大类：用户与权限、邮件核心、附件管理、智能分析、联系人。

核心关系链：用户关联邮箱账号，账号下有关联的文件夹，文件夹里有邮件，每封邮件有多个收件人。邮件和附件是一对多，邮件和分析结果是一对一，分析结果和威胁指标是一对多。

设计规范：主键统一用 BIGINT 自增，软删除用统一的 deleted 字段配合 MyBatis-Plus 的 @TableLogic 自动过滤，邮件去重靠 account_id 加 message_uid 唯一索引。

---

## 第 7 页 · 安全加固实战（60 秒）

这页我想重点讲，因为这是我在项目中学到最多的部分。

通过系统的代码审查，我发现了 15 项安全漏洞，分成四个维度：认证安全、接口防护、数据安全、配置安全。

举几个关键的。第一个，SecurityUtils 在未认证时返回了硬编码的 admin 用户——这意味着任何绕过过滤器的请求都能以管理员身份操作。修复方案是改为抛出异常。

第二个，UserRegistryService 里硬编码了默认密码 "password"——任何人看代码都知道。修复方案是改为通过环境变量注入。

第三个，JWT Secret 的默认值是 "replace-with-at-least-32-bytes-secret"——这个占位符本身就是弱密钥。修复方案是启动时校验，拒绝空值和太短的密钥。

第四个，全局异常处理把 `exception.getMessage()` 直接返回给前端——内部错误细节就全部暴露了。修复方案是记录日志但返回通用提示。

还有登录限流、CORS 显式配置、文件上传大小限制等等。这些修复让我深刻理解了「安全是系统性的，没有一个漏洞是孤立的」。

## 第 8 页 · 部署方案（45 秒）

部署用了 Docker Compose 管理 7 个容器。Nginx 在最前面做反向代理和 SSL 终端，后端跑在 8080，MySQL、Redis、MinIO 各自独立。

线上环境跑在 Debian 12 上，域名 panel.x12w.com，Let's Encrypt 自动签发证书，每天凌晨 3 点自动续期。写了一键部署脚本 deploy.sh，支持 build、start、stop、restart、status、logs、update 七个命令。

所有密码和密钥都通过 .env 文件注入，不提交到 Git。部署时如果没设置 JWT_SECRET，脚本会自动生成临时密钥。

这个是从 Git 仓库实时统计的数据。后端约 30 个 Java 类，前端约 10 个源文件，Git 提交 30 多次，数据库 14 张表。

## 第 10 页 · 技术亮点（60 秒）

总结四个亮点。

第一，**真实的邮件收发**——不是 Mock 不是演示。通过 Jakarta Mail 真正调用 SMTP 发信、IMAP 收信。SSL/TLS 协议自适应，已经用 Resend SMTP 成功发送到 Gmail。

第二，**插件化 AI 引擎**——Python 做分析、Java 做调用、ABI 做桥梁。超时熔断、降级 fallback、版本回溯，这三点保证了 AI 管线的稳定性和可维护性。

第三，**安全纵深防御**——从代码审查中发现并修复了 15 项漏洞，建立了从认证到接口到数据到配置的四层防御体系。

第四，**生产级可部署**——不是只能在本机跑，而是真正部署到了公网服务器，配了 SSL，有一键脚本，可以随时更新。

迭代历程也展示了项目的完整开发过程，从基础框架到部署上线，每个阶段都有明确的目标和交付物。

总结一下，这个项目实现了从零到一的全栈邮件系统，打通了 SMTP/IMAP 真实收发闭环，集成了 AI 智能分析，修复了 15 项安全漏洞，并且已经部署上线。
